## 5. Трактовки, которые нужно подтвердить ❓

От них напрямую зависит точность. Эталонные метки и промпт должны следовать одной трактовке.
Полный свод правил разметки по каждому критерию — `docs/LABELING.md`.

| # | Вопрос | Наша трактовка | Почему |
|---|---|---|---|
| И1 | c07: «Пожалуйста. Хорошего вечера!» без итога и без предложения помощи | **Нет** | В правиле «подвёл итог **или** предложил помощь **и** попрощался»: одного прощания мало |
| И2 | c02: оператор сразу ответил, ничего не уточняя, потому что данных хватало | **N/A**, а не Да | N/A — «данных для ответа хватало с самого начала» |
| И3 | c01: приветствие бота не считается; нужен первый ответ **оператора** на языке клиента с именем | Да только если оператор и поздоровался, и представился в первом ответе | Оценивается оператор, бот — контекст |
| И4 | Грубая ошибка не обнуляет итог | Итог считаем как обычно, флаг отдельно | C стр.2 п.5: «грубые ошибки отметьте отдельно». Если у организаторов итог обнуляется, мы разойдёмся на этих диалогах |
| И5 | Округление «до двух знаков» — половина вверх (как ROUND в Excel) | Половина вверх | Банковское округление Python дало бы другое значение на x.xx5 |
| И6 | Порог первой реакции 3 минуты | **Не оценивается**: скорость только через предупреждение об ожидании | C стр.2: «порог первой реакции в 3 минуты, теги и вложения в оценку не входят» |
| И7 | Звонки: веса и N/A те же, что у чатов | Те же | Письмо меняет только смысл c04 и c06 |
| И9 | Наши трактовки И1–И7 в промпт пока **не** добавлены | Промпт содержит только текст чек-листа | Пробный прогон: модель оценивает мягко (все 4 диалога = 100, c07 «Да» на одно прощание — против И1). Добавлять трактовки — только после эталонных меток, с замером на dev |
| И8 | Чем мерится «близость к эталону» | Считаем и совпадение по критериям, и ошибку итога | Организаторы метрику не назвали. **Стоит спросить у них** |

## 6. Как проверить харнесс самостоятельно

```bash
.venv/Scripts/python.exe -m pytest -q
```

```bash
.venv/Scripts/python.exe -m cqa checklists
```

```bash
.venv/Scripts/python.exe -m cqa run --group DEV --evaluator optimistic
```

Чтобы увидеть отчёт с цифрами, заполните `answers` у пары диалогов в `eval/goldens/DEV.jsonl`
(значения `"yes"`, `"no"`, `"na"` или число шкалы) и повторите `run`: в `runs/<id>/report.md`
появятся метрики по каждому критерию. Проверить подсчёт балла вручную: правило S4 выше
(пример 77.69).
